# ۸. Hysteria2، WireGuard و نود مجزا

[فهرست](README.md)

**این فصل راهنمای طراحی و تنظیم صریح است، نه وعدهٔ نصب یک‌کلیکی.** نسخهٔ فعلی این دو گزینه را خودکار نمی‌سازد. پایهٔ PasarGuard امکانات مرتبط دارد؛ باید نود و هستهٔ سازگار را مطابق مستندات نسخه انتخاب کنی.

## چرا جدا؟

Hysteria2 مبتنی بر QUIC/UDP است. WireGuard هم UDP و پیکربندی رابط، route/NAT و احتمالاً TUN/دسترسی کرنل می‌خواهد. Docker این مخزن صرفاً با اضافه‌کردن اسم یک پروتکل این پیش‌نیازها را نمی‌سازد. public HTTP domain در Railway معادل UDP نیست.

## مسیر نود مجزا

۱. VPS یا نود مجاز با دسترسی شبکهٔ لازم تهیه کن؛ API مدیریت آن را محدود و دارای TLS/auth نگه دار.
۲. نسخهٔ PasarGuard Node و هستهٔ سازگار را از release رسمی مشخص کن؛ latest شناور برای محیط عملیاتی انتخاب نکن.
۳. کلید API و گواهی نود را در محیط سرور تولید/نگهداری کن؛ در چت، GitHub یا کانال تلگرام نفرست.
۴. نود را در پنل با address، پورت API، connection type و CA صحیح ثبت کن.
۵. هستهٔ اختصاصی همان خانواده را به نود وصل کن؛ نوع WireGuard با Xray یکی نیست.
۶. inbound، host، group و قالب کاربری اختصاصی بساز تا همهٔ کاربران بی‌اختیار آن را دریافت نکنند.
۷. یک کاربر محدود آزمایشی بساز؛ مصرف و انقضا و لغو دسترسی را تست کن.

## Hysteria2

- UDP عمومی و عدم محدودیت/حذف شدید UDP در مسیر لازم است.
- گواهی معتبر و نام دامنهٔ مطابق SNI؛ `allowInsecure` راه‌حل دائم نیست.
- هسته/نود باید احراز هویت کاربران و آمار پنل را درست متصل کند؛ فایل YAML یک سرور مستقل را بدون اتصال accounting به‌عنوان نود مدیریت‌شده معرفی نکن.
- bandwidth غیرواقعی می‌تواند ازدحام و افت کیفیت بسازد؛ با اندازه‌گیری تنظیم کن.

مرجع رسمی: https://v2.hysteria.network/docs/getting-started/Server/

## WireGuard

- پورت UDP، forwarding، route و NAT، کلید هر peer، DNS و MTU باید مشخص باشند.
- با تغییر route روی سرور، اتصال SSH را قطع نکن؛ کنسول اضطراری داشته باش.
- `privileged: true` راه میانبر پیش‌فرض نیست؛ فقط capability/device واقعاً لازم را بعد از بررسی بده.
- کلید خصوصی peer را عمومی نکن. کلاینت رسمی WireGuard الزاماً لینک VLESS یا ساب چندپروتکلی را نمی‌خواند؛ خروجی WireGuard مناسب لازم است.

مرجع: https://www.wireguard.com/quickstart/ و https://docs.pasarguard.org/en

## معیار «آماده» بودن

handshake موفق، انتقال داده، DNS، مصرف هر کاربر، قطع دسترسی بعد از disable/expire، restart و بازیابی بکاپ باید آزموده شوند. تا آن زمان عبارت «پشتیبانی پایه» را با «یکپارچه و تست‌شده در SABI-RAY» یکی ندان.
