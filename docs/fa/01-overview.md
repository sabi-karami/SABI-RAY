# ۱. شناخت ساختار و انتخاب روش نصب

[فهرست آموزش‌ها](README.md)

## پنل چه کار می‌کند؟

SABI-RAY مدیریت کاربران و نمایندگان، حجم، انقضا، گروه‌ها، هاست‌ها، اشتراک‌ها و نودها را از PasarGuard به ارث می‌برد. ظاهر و هویت SABI-RAY، راه‌اندازی امن‌تر، پیش‌تنظیم‌ها و آزمون‌های این توزیع روی آن اضافه شده‌اند؛ پروتکل یا رمزنگاری اختراعی جدیدی نداریم.

مسیر اتصال وب:

```text
کلاینت ← TLS روی دامنه:443 ← Caddy یا edge میزبان ← nginx:8080 ← Xray روی loopback
                                            └── پنل/API:8000
```

مسیر مستقیم اختیاری:

```text
کلاینت REALITY → دامنه مستقیم:11443/TCP → Xray
کلاینت Shadowsocks → دامنه مستقیم:11444/TCP → Xray
```

نود داخلی با API روی `127.0.0.1:62050` صحبت می‌کند. این پورت را عمومی نکن. پایگاه داده، کلید نود و شناسهٔ نصب در Volume مسیر `/var/lib/pasarguard` هستند. پاک‌کردن کانتینر با پاک‌کردن Volume یکسان نیست.

## سه مسیر نصب

| روش | مناسب برای | محدودیت |
|---|---|---|
| VPS + Docker + Caddy | اختیار بیشتر روی TCP و TLS | نگهداری سیستم و فایروال با توست |
| Docker پشت reverse proxy خودت | زیرساخت موجود | TLS و trusted proxy را خودت درست تنظیم کن |
| Railway | فقط پس از روشن‌شدن اجازهٔ میزبان | AUP و نوع دسترسی شبکه؛ مسیر HTTPS معادل UDP نیست |

پیشنهاد برای شروع: نصب جدید روی VPS مجاز، سه پروفایل WS پیش‌فرض، سپس تست کلاینت. نام بیشتر یا پنج fingerprint روی یک سرور الزاماً مسیر مستقل و سریع‌تر نمی‌سازد.

## منابع و هزینه

ساخت داشبورد نیازمند RAM/دیسک و دسترسی به مخازن بسته‌هاست؛ تضمین عدد ثابت برای هر میزبان نداریم. برای شروع آزمایشی منابع کافی رزرو و مصرف واقعی را بررسی کن. هزینهٔ ترافیک خروجی و قوانین میزبان جدا از رایگان‌بودن سورس‌اند. SQLite برای همین استقرار یک‌Replica در نظر گرفته شده؛ با چندReplica روی فایل مشترک آن را مقیاس نده.

**خروجی مورد انتظار:** روش نصب، دامنه، دسترسی سرور و اجازهٔ میزبان مشخص باشد؛ هنوز هیچ داده‌ای تغییر نمی‌کند.
